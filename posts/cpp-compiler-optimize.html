概述与代码

不多说直接说重要的：加法对应的汇编指令是 add。

编译器会根据优化方式选择最匹配的优化方案，常用优化方案如下：

  1. O1 选项：生成文件占用空间最少
  2. O2 选项：执行效率最快

在 VS 里面 Release 默认开启 O2——执行效率最快。Debug 中使用 /Od /Z1。

#include <stdio.h>

int main(int argc, char* argv[]){
    10+20;
    int n1 = 0;
    int n2 = 0;
    n1 = n1 + 1;
    n1 = 1 + 2;
    n1 = n1 + n2;

    printf("%d\r\n", n1);
    return 0;
}

CMake 文件：

cmake_minimum_required(VERSION 3.25)
project(plas)

set(CMAKE_CXX_STANDARD 14)

set(CMAKE_CXX_FLAGS "${CMAKE_CXX_FLAGS} -O2")
set(CMAKE_CXX_FLAGS_DEBUG "-O2 -g")

add_executable(plas main.cpp)

注意默认是 Debug，CLion 的 Debug 会覆盖 MSVC 所以多加了一行。

总结

  1. 两个常量相加的情况下，编译器会直接计算出结果，将这个结果作为立即数参加运算，减少程序在运行期的运算。
  2. 当有变量参加加法运算的时候，会先取出内存中的数据，放入通用寄存器中再进行加法运算得到结果，并放回变量创建的内存中。

开启 O2 选项之后，因为效率优先，无用代码会被删除，将可以合并的代码归并处理。看前面的代码的例子，n1 = n1 + 1 这样的代码会被删除，因为后面又进行了新的赋值，但前面的代码没有对 n1 进行访问，所以可以删除。

所以这里的代码使用了两种优化方案。在编译器运行的时候也是常用的操作。以下是两个方案的详细说明：

常量传播

将编译期间可以算出结果的变量转换成为常量，这样就能减少变量的使用。

int main(int argc, char* argv[]){
    int n = 1;
    printf("n = %d \r\n", n);
    return 0;
}

运算期间，变量 n 能计算出来，那么减少引用次数加快速度（和 CPU 流水线也有关系，后面会写到），就会直接使用常量 1 来代替。

等价代码：

int main(int argc, char* argv[]){
    printf("n = %d \r\n", 1);
    return 0;
}
常量折叠

当出现多个变量进行计算的时候，并且编译器能在编译时间计算出结果，源代码的计算都会被计算结果代替。

int main(int argc, char* argv[]){
    int n = 1 + 5 - 3 * 6;
    printf("n = %d\r\n", n);
    return 0;
}

此时计算不会生成汇编，会直接计算出答案直接替换。

等价代码：

int main(int argc, char* argv[]){
    int n = -12;
    printf("n = %d\r\n", n);
    return 0;
}

又因为 n 现在是赋值输出，可以进行常量传播。所以最后的代码就是：

int main(int argc, char* argv[]){
    printf("n = %d\r\n", -12);
    return 0;
}

VC++ 在开启 O2 优化方案后会尝试使用常量替换变量。在程序的逻辑中变量没有修改过，上下文不存在对变量的取地址或者间接访问操作，那么这个变量就等价于常量，编译器就可以删除变量修改为常量。

代码

接下来修改代码再看。将 0 修改成了 argc：

#include <stdio.h>

int main(int argc, char* argv[]){
    10+20;
    int n1 = argc;
    int n2 = argc;
    n1 = n1 + 1;
    n1 = 1 + 2;
    n1 = n1 + n2;

    printf("%d\r\n", n1);
    return 0;
}
