概述

32 位整数在参与算术运算时存在两类越界行为：结果超出存储空间后，无符号数表现为进位、有符号数表现为溢出，二者由不同的标志位记录。本文先解释这两类现象，再通过自增自减表达式在 MinGW 与 MSVC（64→64 / 64→32）下的三组汇编输出，分析 ++/-- 前后缀在指令层面的真实语义。

算术结果溢出

解释起来很简单：4 字节 32 位的内存空间经过运算之后得到的结果超过了存储空间的大小。对于有符号数而言，会由正数变成负数。

示例代码
for (int i = 1; i > 0; i++) {
    printf("%d", i);
}

i 从 1 开始不断自增并打印，当结果超过 INT_MAX 后，最高位（符号位）被破坏，正数变为负数，条件 i > 0 不再成立，循环随之结束。这类依赖有符号溢出的写法属于未定义行为，实际结果依赖编译器与运行环境。

无符号：进位（CF）

无符号数发生存储范围超过叫进位。因为没有符号位，进位不会破坏数据本身；出现问题时，溢出到最高位之外的那一位 1 会被存储在 CF（Carry Flag）寄存器中，查看该标志位就能看到。

有符号：溢出（OF）

有符号数超出存储范围叫溢出。很简单——破坏掉了有符号数的正负标记位（最高位）。检查 OF（Overflow Flag）寄存器即可，具体细则参考 Intel 手册。

自增自减

示例代码
#include <stdio.h>

int main(int argc, char* argv[]){
    int n1 = argc;
    int n2 = argc;
    n2 = 5 + (n1++);
    n2 = 5 + (++n1);
    n1 = 5 + (n2--);
    n1 = 5 + (--n2);
    return 0;
}

前后缀语义分析

这三组汇编说明的就是一件事：++ 在前在后的区别。MinGW 偏好 lea 的做法——在一条指令里算出新值并存回变量，旧值保留在寄存器里继续参与后续运算；MSVC 更倾向于使用中间变量来处理。

后缀自增（以 n2 = 5 + (n1++) 为例）：

t  = a + 5; a = a + 1; b = t;
→ 等价于  b = 旧a + 5; a = 旧a + 1;

后缀自减（以 n1 = 5 + (n2--) 为例）：

t2 = b + 5; b = b - 1; a = t2;
→ 等价于  a = 旧b + 5; b = 旧b - 1;

前缀 ++n/--n 则先完成自增/自减，参与运算的已经是新值：汇编中表现为 addl/subl $0x1（或 incl/decl）先行写回变量，随后再读取该变量与 5 相加。

总结

  • 进位 vs 溢出：无符号数越界叫进位，进位位保存在 CF；有符号数越界叫溢出，符号位被破坏，由 OF 记录。
  • 后缀 ++/--：先取旧值参与运算，再更新变量；MinGW 用 lea 一条指令同时保留旧值与写回新值，MSVC 用中间变量暂存旧值的运算结果。
  • 前缀 ++/--：先更新变量（addl/subl $0x1 或 incl/decl 写回），再读取新值参与运算。
  • 逆向识别时，看到紧邻算术运算的 lea 0x1(%rax),%edx + 写回 + 旧值继续相加的模式，即可判定为前后缀自增自减的表达式。
