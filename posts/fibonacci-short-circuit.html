概述

逻辑运算符 || / && 具有短路求值特性：左操作数已经能决定整个表达式的结果时，右操作数不再求值。把「赋值」塞进右操作数，就能让短路承担 if 的职责——这也是「一行实现斐波那契」的由来。本文用这段代码的 MinGW 汇编说明短路表达式为什么等价于分支结构，再对比三目运算符在 MinGW 与 MSVC 下的汇编形态，以及优化级别带来的分支 / 无分支差异。

表达式短路

这段技术很有意思，先给出方案：一行实现斐波那契。

示例代码
#include <stdio.h>

int flib(int num){
    (num < 2) || (num = flib(num - 1) + flib(num - 2));
    return num;
}

int main(int argc, char* argv[]){
    for (int i = 1; i < 10; i++) {
        printf("%d\t", flib(i));
    }
    return 0;
}

关键在于第二行：num < 2 成立时（递归出口），|| 直接短路，右侧的赋值不会执行；不成立时才求值右侧，先把 num 赋成前两项之和，再返回。也就是说这条语句其实可以代替 if。

MinGW 汇编
flib(int):
    push   %rbp
    push   %rbx
    sub    $0x28,%rsp
    lea    0x20(%rsp),%rbp
    mov    %ecx,0x20(%rbp)
    cmpl   $0x1,0x20(%rbp)
    jle    0x7ff6ddfb1719          ; <flib(int)+57>
    mov    0x20(%rbp),%eax
    sub    $0x1,%eax
    mov    %eax,%ecx
    call   0x7ff6ddfb16e0          ; <flib(int)>
    mov    %eax,%ebx
    mov    0x20(%rbp),%eax
    sub    $0x2,%eax
    mov    %eax,%ecx
    call   0x7ff6ddfb16e0          ; <flib(int)>
    add    %ebx,%eax
    mov    %eax,0x20(%rbp)
    cmpl   $0x0,0x20(%rbp)
    mov    0x20(%rbp),%eax
    add    $0x28,%rsp
    pop    %rbx
    pop    %rbp
    ret
汇编解读
  • 参数入栈：mov %ecx,0x20(%rbp) 把第一个整型参数 num 存到栈上，后面对 num 的所有读写都走这个栈槽（-O0 的典型特征）。
  • 短路判定就是分支：cmpl $0x1,0x20(%rbp) 比较 num 与 1，jle 在有符号「小于等于」时跳转到函数尾部（对应递归出口）。短路求值在指令层面被编译成了 cmp + jcc，与手写 if (num < 2) return num; 的分支完全同构。
  • 递归调用两次：右侧表达式先算 flib(num - 1)，用 ebx 暂存结果；再算 flib(num - 2)，最后 add %ebx,%eax 求和并写回栈槽，实现赋值 num = ...。
  • 表达式真值被丢弃：末尾的 cmpl $0x0,0x20(%rbp) 是编译器对整个 || 表达式做真值判定留下的痕迹——该语句的结果并没有被使用，随后 mov 0x20(%rbp),%eax 才是 return num; 的取值。
  • 结论：这种写法和 if 很像，都是根据比较结果决定是否跳转，属于典型的分支结构。其他逻辑运算符（&&、! 组合）同理。

条件表达式

条件表达式就是三目运算符 cond ? a : b，本质上是带返回值的分支结构，其汇编形态与上面的短路写法非常相似。

四种转换方案

表达式转换方案一共有四种：

  • 方案 1：表达式 1 简单，表达式 2 和表达式 3 两者为常量且差值为 1。
  • 方案 2：表达式 2 和表达式 3 两者为常量且差值大于 1。
  • 方案 3：表达式 2 或表达式 3 含有变量。
  • 方案 4：表达式 2 或表达式 3 含有变量表达式。

以 printf("%d", argc == 5 ? 5 : 6); 为例（属于方案 2：两个分支为常量、差值为 1），在未开启优化时并不会使用 setcc / cmov 进行优化，因此编译结果保留跳转。

MinGW 汇编
main(int, char**):
    push   %rbp
    mov    %rsp,%rbp
    sub    $0x20,%rsp
    mov    %ecx,0x10(%rbp)
    mov    %rdx,0x18(%rbp)
    call   0x7ff6817d1807          ; <__main>
    cmpl   $0x5,0x10(%rbp)
    jne    0x7ff6817d1701          ; <main(int, char**)+33>
    mov    $0x5,%eax
    jmp    0x7ff6817d1706          ; <main(int, char**)+38>
    mov    $0x6,%eax
    mov    %eax,%edx
    lea    0x88f1(%rip),%rax       ; 0x7ff6817da000
    mov    %rax,%rcx
    call   0x7ff6817d8e10          ; <printf(char const*, ...)>
    mov    $0x0,%eax
    add    $0x20,%rsp
    pop    %rbp
    ret
MSVC 汇编
main(int,char **):
    movq   %rdx, 0x10(%rsp)
    movl   %ecx, 0x8(%rsp)
    pushq  %rdi
    subq   $0x30, %rsp
    cmpl   $0x5, 0x40(%rsp)
    jne    0x1400014df             ; <+31> at main.cpp:4
    movl   $0x5, 0x20(%rsp)
    jmp    0x1400014e7             ; <+39> at main.cpp:4
    movl   $0x6, 0x20(%rsp)
    movl   0x20(%rsp), %edx
    leaq   0x86be(%rip), %rcx
    callq  0x140001195             ; printf
    xorl   %eax, %eax
    addq   $0x30, %rsp
    popq   %rdi
    retq

两者的结构完全一致：cmp 判断条件 → jne 跳到「假」分支 → 两条路径各自把结果写回寄存器或栈槽 → jmp 汇合。区别只在落地位置：MinGW 直接写 eax，MSVC 把常量写进栈槽再取到 edx 传参。

优化级别差异

没有使用 setcc / cmov 进行优化只是因为没开优化，开启后就会有：argc == 5 ? 5 : 6 会被编译成无分支（branchless）的 setcc 形态。

优化级别形态特征指令
/Od（未优化）两条 mov 到栈槽 + 跳转jne / movl $5,mem / movl $6,mem
/O1常为 setcc + add，或 CMOVsetne / add，或 cmovel
/O2无分支，CMOV 或 setcc + addcmovel 或 setne %dl; add

分支预测

条件表达式最终转换出的汇编与分支结构表现极其相似，判断比较的方式也与表达式短路一致。从 Pentium（P5）时代开始，CPU 就引入了针对分支指令（if-then-else）导致流水线失败的数据处理方法——分支预测：由 CPU 猜测程序的跳转方向并提前取指执行，猜对则流水线不中断。因此在复杂的条件表达式中，使用分支通常比条件传送的效率更高。

总结

  • 短路即分支：(num < 2) || (num = ...) 之所以能替代 if，是因为 || 的短路语义在指令层面就是 cmp + jcc；把赋值写在右侧，跳转与否就等价于「是否执行赋值」。
  • 递归出口靠短路：num < 2 成立时右侧不求值，直接返回 num，这正是斐波那契递归的终止条件。
  • 三目即带值分支：cond ? a : b 在未优化时是 jcc + 两条赋值路径 + jmp 汇合；开启优化后才会被 setcc / cmov 改写成无分支形态。
  • 逆向识别：看到 cmp/test + jcc 后两条互斥的赋值路径再汇合，即可判定为条件表达式或短路表达式；无分支版本则以 setcc（写 0/1 字节）配合 add/sub，或 cmovcc 移动数据的形式出现。
  • 性能取舍：分支预测让可预测的分支开销极低，而 cmov 在数据依赖长、分支高度随机时更稳；编译器是否改写取决于优化级别与具体形态，逆向时不看优化级别很容易误判源码写法。
