前置知识

Content Security Policy（内容安全策略），用于定义脚本和其他资源从何处加载或者执行，总结来说就是白名单机制，会一定程度缓解 XSS 脚本问题。CSP 以白名单机制对网站加载或执行的资源起作用，在网页中策略通过 HTTP 头信息或者 meta 元素定义。

CSP 虽然提供了强大的安全保护，但它也令 eval() 及相关函数被禁用、内嵌的 JavaScript 代码将不会执行、只能通过白名单来加载远程脚本。

Low 难度

代码分析
<?php

$headerCSP = "Content-Security-Policy: script-src 'self' https://pastebin.com hastebin.com www.toptal.com example.com code.jquery.com https://ssl.google-analytics.com https://digi.ninja ;";

header($headerCSP);

?>
<?php
if (isset ($_POST['include'])) {
$page[ 'body' ] .= "
    <script src='" . $_POST['include'] . "'></script>
";
}
?>

源码对 HTTP 头定义了 CSP，指定了可接受的外部 JavaScript 资源白名单。抓包可以看到 Content-Security-Policy 头中允许从 pastebin.com、hastebin.com、digi.ninja 等域名加载脚本。

Medium 难度

代码分析
<?php

$headerCSP = "Content-Security-Policy: script-src 'self' 'unsafe-inline' 'nonce-TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=';";

header($headerCSP);

header ("X-XSS-Protection: 0");

?>
<?php
if (isset ($_POST['include'])) {
$page[ 'body' ] .= "
    " . $_POST['include'] . "
";
}
?>

合法来源发生变化，script-src 设置了特殊值：'unsafe-inline' 允许执行页面内嵌的 <script> 标签，nonce 值在每次 HTTP 回应给出一个授权 token。但这里的 nonce 是固定的（base64 解码为 "Never going to give you up"）。

漏洞利用

通过内联注入，使用正确的 nonce 值即可执行脚本：

<script nonce="TmV2ZXIgZ29pbmcgdG8gZ2l2ZSB5b3UgdXA=">alert("1")</script>

High 难度

代码分析
<?php
$headerCSP = "Content-Security-Policy: script-src 'self';";

header($headerCSP);

?>
<?php
if (isset ($_POST['include'])) {
$page[ 'body' ] .= "
    " . $_POST['include'] . "
";
}
?>

high.js:

function clickButton() {
    var s = document.createElement("script");
    s.src = "source/jsonp.php?callback=solveSum";
    document.body.appendChild(s);
}

function solveSum(obj) {
    if ("answer" in obj) {
        document.getElementById("answer").innerHTML = obj['answer'];
    }
}

var solve_button = document.getElementById("solve");
if (solve_button) {
    solve_button.addEventListener("click", function() { clickButton(); });
}

high.php 设置 CSP 只允许同源脚本加载。页面通过 JSONP 调用 source/jsonp.php?callback=solveSum，其中 callback 参数是动态传入的。

Impossible 难度

代码分析
<?php

$headerCSP = "Content-Security-Policy: script-src 'self';";

header($headerCSP);

?>
<?php
if (isset ($_POST['include'])) {
$page[ 'body' ] .= "
    " . $_POST['include'] . "
";
}
?>

impossible.js:

function clickButton() {
    var s = document.createElement("script");
    s.src = "source/jsonp_impossible.php";
    document.body.appendChild(s);
}

function solveSum(obj) {
    if ("answer" in obj) {
        document.getElementById("answer").innerHTML = obj['answer'];
    }
}

var solve_button = document.getElementById("solve");
if (solve_button) {
    solve_button.addEventListener("click", function() { clickButton(); });
}

Impossible 级别的 JSONP 调用不接收 callback 参数，而是硬编码了调用的函数名。攻击者无法通过 include 参数控制回调函数，CSP 策略也锁定为只允许同源脚本，有效提高了安全性。
